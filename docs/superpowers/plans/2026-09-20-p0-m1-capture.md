# P0 M1 — Capture: real Claude Code sessions become confirmed checkpoints

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **In this repo:** Devin CLI implements each task from a brief in `.devin/briefs/`; Claude writes the briefs and runs Task 7; one Opus subagent reviews the whole batch at the end (never per task).

**Goal:** While a real Claude Code session works, a hook hands each event to Mida in a few milliseconds, a cheap model turns the transcript into a checkpoint (a structured note of where the work stands), and that checkpoint is encrypted and registered on Monad under Claude Code's own agent key.

**Architecture:** Two new pure packages — `packages/checkpoint` (shape, validation, merge, render; no I/O) and `packages/compiler` (transcript reader → secret scrubber → model command → validated checkpoint). `apps/midad` gains a disk queue, a drainer that owns the protocol calls, and a hook entry point. The drainer is a short-lived process in M1; M2 turns the same drainer into the long-running daemon behind a socket, without changing the queue format.

**Tech Stack:** TypeScript (ESM, run through `tsx`), Node 25, Vitest, pnpm workspaces, viem, the existing `@mida/*` packages. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-09-20-p0-handoff-design.md` — §4, §5C, §5D (merge rule), §8, and amendments A2, A4, A5, A13. The spike at `spike/` is the reference implementation for everything marked PORT below; nothing may import from it.

## Global Constraints

- Dates: M1 is **Sep 21–23** (A13). Code freeze for the whole build is Sep 30.
- Never open, print or edit `.env`. Never read `~/.codex`, `~/.claude`, `~/.mida`.
- Every model subprocess runs with `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` removed from its environment (spike bug G2: an exported key silently produces an empty, successful-looking run).
- The user's original request is copied from the transcript **by code**, never written by the model (spike bug H1). If the model returns an `originalRequest`, drop it and log the key name.
- A hook must never block or pollute the agent: stdout stays empty for capture events, exit code is always 0, and the hook process returns in under 1.5 s whatever the model does.
- Logs record key names, counts and timings. Never values, never transcript text.
- Payload cap: the encoded checkpoint value must be ≤ 65,536 bytes (protocol limit).
- Agents write with provenance `AGENT_INFERRED` only, into namespace `projects.current`, kind `EPISODE`.
- The save's ID must change whenever the transcript grows and must not change on a retry (spike bug F1).
- Tests for ported code are ported with it, including every F/G/H regression test. Never weaken an assertion.
- Devin: one command per call, no `&&`, `|`, `;`, `>`; never `pnpm mida`; never the testnet; `pnpm install` only in the steps that name it.
- Run tests with `pnpm vitest run <path>`. Node 25 cannot run `node --test test/`.

```ts
import type { Checkpoint } from "./schema.js"

// StoredCheckpoint and MergedHandoff interfaces exactly as in this task's Interfaces block.

const byTime = (a: StoredCheckpoint, b: StoredCheckpoint) =>
  Date.parse(a.checkpoint.createdAt) - Date.parse(b.checkpoint.createdAt)

function distinct<T>(items: T[]): T[] {
  const seen = new Set<string>()
  return items.filter((item) => {
    const key = JSON.stringify(item)
    if (seen.has(key)) return false
    seen.add(key)
    return true
  })
}

function latest<T>(values: T[], isEmpty: (v: T) => boolean, fallback: T): T {
  for (let i = values.length - 1; i >= 0; i -= 1) if (!isEmpty(values[i]!)) return values[i]!
  return fallback
}

export function mergeCheckpoints(all: readonly StoredCheckpoint[]): MergedHandoff | null {
  if (all.length === 0) return null
  if (new Set(all.map((s) => s.projectId)).size !== 1) throw new Error("mergeCheckpoints needs checkpoints from one project")
  const sorted = [...all].sort(byTime)
  const sessions = new Set<string>()
  let cursor: string | null = sorted[sorted.length - 1]!.sessionId
  while (cursor !== null && !sessions.has(cursor)) {
    sessions.add(cursor)
    const first = sorted.find((s) => s.sessionId === cursor)
    cursor = first?.continuesSession ?? null
  }
  const scope = sorted.filter((s) => sessions.has(s.sessionId))
  const cps = scope.map((s) => s.checkpoint)
  return {
    originalRequest: cps.find((c) => c.originalRequest !== null)?.originalRequest ?? null,
    objective: latest(cps.map((c) => c.objective), (v) => v === "", ""),
    remainingPlan: latest(cps.map((c) => c.remainingPlan), (v) => v.length === 0, []),
    unresolvedIssue: latest(cps.map((c) => c.unresolvedIssue), (v) => v === null || v === "", null),
    nextAction: latest(cps.map((c) => c.nextAction), (v) => v === "", ""),
    decisions: distinct(cps.flatMap((c) => c.decisions)),
    rejected: distinct(cps.flatMap((c) => c.rejected)),
    constraints: distinct(cps.flatMap((c) => c.constraints)),
    artifacts: distinct(cps.flatMap((c) => c.artifacts)),
    progress: distinct(cps.flatMap((c) => c.progress)),
    provenance: scope.map((s) => ({ agent: s.checkpoint.agent, createdAt: s.checkpoint.createdAt, contextId: s.contextId, compiledBy: s.compiledBy })),
  }
}
```

Known limit, stated on purpose: `unresolvedIssue` can never be cleared by a later `null`, because a delta save also writes `null`. Task 4 makes the compiler write the literal string `"none"` when the transcript shows the issue was resolved; `latest` treats `"none"` as a real value and the renderer prints it.

```ts
export interface CaptureJob { id: string; agent: string; event: HookEvent; sessionId: string; transcriptPath: string; cwd: string; error: string | null; at: string }
export function enqueue(home: MidaHome, job: Omit<CaptureJob, "id" | "at">, now?: () => Date): CaptureJob

export interface DrainDeps { home: MidaHome; open: () => Promise<Runtime>; compile: typeof compileCheckpoint; now?: () => Date; minGapMs?: number }
export async function drainOnce(deps: DrainDeps): Promise<{ saved: number; skippedUnchanged: number; skippedTooSoon: number; failed: number }>
```

Rules the code must follow (each has a test below):
1. `runHook` returns without doing anything when `env.MIDA_INNER === "1"` (the model subprocess is itself a Claude Code run; without this the hook captures its own compiler forever).
2. `runHook` never throws and writes nothing to stdout. Bad stdin JSON, an unknown event name, a missing `transcript_path`: one line in `logs/hook.jsonl`, return.
3. A job is one JSON file `queue/<iso-time>-<random>.json`, written through the home's atomic write.
4. `drainOnce` groups jobs by `sessionId` and processes each session once, using the newest job; if any job of that session is a flush event, the session is treated as a flush. The older jobs of that session are removed without work.
5. Per session it keeps `queue/state/<sessionId>.json` = `{ transcriptBytes, lastLineHash, savedAt }`. Unchanged transcript → skip (`skippedUnchanged`), even for a flush event, and remove the job. Changed but less than `minGapMs` (default 60,000) since `savedAt` and not a flush → skip (`skippedTooSoon`) **and keep the job**, so the next drain picks it up. Flush events ignore the gap.
6. No `.mida/project.json` above `cwd` → the job is removed and one log line says the folder is not a Mida project. (`mida approve` creating that file is M2; tests create it by hand.)
7. `continuesSession` is `null` in M1. (M2's session-start hook records which handoff a session began from.)
8. A compile failure or a save failure leaves the job in place, increments `failed`, and writes the reason (never transcript text) to `logs/drain.jsonl`. A job older than 24 h, or whose transcript file no longer exists, is moved to `queue/bad/`.
9. `Runtime.open` holds `midad.lock`. If the lock is held, `drain-main` exits 0 quietly: the holder will drain. After finishing, `drain-main` calls `drainOnce` again while it made progress and jobs remain, so nothing is stranded.
10. `hook-main.ts` reads stdin (cap 1 MB), takes the agent name from `argv[2]`, and calls `runHook` with `spawnDrainer` = `spawn(process.execPath, ["--import", "tsx", drainMainPath], { detached: true, stdio: "ignore", cwd: repoRoot, env: process.env })` followed by `unref()`. The drainer reads the network from `~/.mida/network.json`, which `init` now writes: `{ chainId, rpcUrl, deployment }`, no secret in it. The drainer never loads `.env`: it holds only agent keys from the home folder.
